취업·이직용 개인 포트폴리오 웹사이트 구현 요구사항

이 문서를 기준으로 실제 운영 가능한 포트폴리오 웹사이트를 구현한다. 화면뿐 아니라 관리자 인증, 데이터 저장, 이미지 관리, 게시 흐름까지 연결해야 한다.

명시된 요구사항을 우선하고, 세부 구현 방식은 기존 프로젝트 구조와 공식 문서를 확인하여 결정한다. 추가 기능을 임의로 확대하지 않는다.

**1. 목적과 대상**

- 주된 목적: 취업 및 이직.
- 주 방문자: 채용 담당자.
- 기본 언어: 한국어.
- 이름과 직무: 실명 및 한글 표기.
- 핵심 방문 행동: 프로젝트 열람, 이력서 미리보기 및 다운로드.
- 프로젝트의 문제 해결 과정, 본인의 역할, 구현 내용과 결과를 쉽게 파악할 수 있도록 구성한다.
- 실제 개인 정보와 콘텐츠는 추후 제공한다. 확인되지 않은 학력·경력·성과를 실제 정보처럼 작성하지 않는다.

**2. 디자인 방향과 커스텀 구조**

참고 사이트: https://chanhdai.com/

참고 사이트를 디자인의 기반으로 삼되, 사용자 본인의 콘텐츠와 브랜딩으로 구성한다.

참고할 요소는 콘텐츠 너비, 여백, 테두리, 배경 무늬, 글꼴, 카드 형태, 프로필 배치, 애니메이션이다.

디자인을 쉽게 수정할 수 있도록 다음 항목을 공통 설정으로 관리한다.

- 콘텐츠 최대 너비.
- 색상과 라이트·다크 테마 값.
- 글꼴, 글자 크기, 행간.
- 여백, 테두리, 모서리.
- 배경 무늬.
- 애니메이션 속도와 강도.

카드, 섹션, 프로필, 버튼 등은 재사용 가능한 컴포넌트로 분리한다.

콘텐츠는 관리자에서 수정하고, 디자인과 레이아웃은 공통 설정 및 컴포넌트를 통해 코드에서 수정한다. 초기 버전에 드래그 기반 페이지 빌더나 관리자용 CSS 편집기는 포함하지 않는다.

**3. 페이지와 홈 구성**

| 경로 | 용도 |
|---|---|
| `/` | 포트폴리오 홈 |
| `/projects` | 프로젝트 전체 목록 |
| `/projects/[slug]` | 프로젝트 상세 |
| `/blog` | 블로그 전체 목록 |
| `/blog/[slug]` | 블로그 상세 |
| `/admin` 및 하위 경로 | 관리자 로그인 및 관리 화면 |

홈 섹션 순서는 다음과 같이 고정한다.

프로필 → About me → Education → Stack → Experience → Projects → Blog

- GitHub 활동 표시는 프로필 영역 안에 배치한다.
- 프로필에 프로젝트 열람, 이력서 미리보기·다운로드, GitHub, 이메일 링크를 제공한다.
- 홈에는 대표 프로젝트와 최신 블로그 글의 일부만 표시한다.
- 대표 프로젝트와 최신 블로그 노출 개수는 관리자에서 각각 설정한다. 초기값은 각각 3개다.
- 대표 프로젝트는 관리자가 선택하고 순서를 지정한다.
- 최신 블로그는 최초 게시일 최신순으로 표시한다.
- 공개 가능한 콘텐츠가 설정 개수보다 적으면 실제 개수만 표시한다.
- Projects와 Blog에 각각 ‘전체 보기’를 제공한다.
- 무한스크롤은 전체 목록 페이지에만 적용한다.
- 비어 있는 홈 섹션은 숨기고 해당 헤더 메뉴도 숨긴다.
- 전체 목록 페이지가 비어 있을 때는 빈 상태와 홈으로 돌아갈 수 있는 안내를 제공한다.

**4. 헤더와 이동**

- 헤더는 항상 화면 상단에 고정한다.
- 모바일에서는 메뉴를 접어 표시한다.
- 홈의 메뉴를 누르면 해당 섹션으로 이동한다.
- 홈 이외 페이지에서는 홈의 해당 섹션으로 이동한다.
- 섹션과 본문 목차로 이동할 때 제목이 고정 헤더에 가려지지 않도록 한다.
- 모바일 메뉴는 항목 선택 후 닫힌다.
- 메뉴는 키보드로 조작할 수 있어야 한다.
- 공개 사이트에 상단 검색이나 키워드 검색은 제공하지 않는다.

**5. 테마**

- 라이트, 다크, 시스템 모드를 제공한다.
- 첫 방문 기본값은 시스템 설정이다.
- 사용자가 선택한 모드는 저장하고 새로고침과 페이지 이동 후에도 유지한다.
- 시스템 모드에서는 기기의 테마 변경을 반영한다.
- 다크 테마의 초기 배경은 짙은 회색으로 한다.
- 공개 페이지, 관리자, 코드블록, 메뉴, 편집기, 알림, 대화상자에 일관되게 적용한다.
- 첫 화면에서 잘못된 테마가 잠깐 나타나는 현상을 방지한다.
- 두 테마에서 이미지, 기술 로고, 보조 텍스트의 식별성을 확인한다.

**6. 관리자 인증과 권한**

GitHub 로그인을 사용한다.

- 사전에 등록한 본인 GitHub 계정의 고유 ID만 허용한다.
- 사용자명, 실명, 이메일만으로 관리자 권한을 판단하지 않는다.
- 허용 계정에만 사이트의 관리자 세션을 발급한다.
- 다른 GitHub 계정의 인증 결과는 거절하고 사이트 계정·관리자 세션을 생성하지 않는다.
- 방문자 회원가입과 일반 회원 기능은 제공하지 않는다.
- 공개 화면에는 로그인 버튼을 배치하지 않는다.
- 관리자 접근은 `/admin`에서 시작한다.
- 관리자 화면, 데이터 조회, 생성·수정·삭제, 업로드, 내보내기 등에서 서버 권한 검증을 수행한다.
- 화면에서 버튼을 숨기는 것만으로 접근을 제한하지 않는다.
- 비밀값과 GitHub API 토큰은 서버 환경 설정으로 관리한다.
- 로그아웃, 세션 만료, 로그인 실패를 안내한다.
- 세션 만료로 저장에 실패해도 편집 내용을 지우지 않고 재로그인과 복구 방법을 제공한다.
- 자동저장이나 게시가 실패한 경우 성공한 것처럼 표시하지 않는다.

**7. 데이터 저장과 관리자 범위**

데이터베이스와 직접 구현한 관리자 화면을 사용한다.

- 콘텐츠, Markdown 원문, 메타데이터는 영속적인 데이터베이스에 저장한다.
- 이미지와 PDF는 영속적인 파일 저장소에 저장한다.
- 데이터는 새로고침이나 재배포 후에도 유지되어야 한다.
- Vercel 배포 환경의 임시 파일시스템을 영구 저장소로 사용하지 않는다.

관리자는 다음 항목을 관리할 수 있어야 한다.

| 대상 | 관리 기능 |
|---|---|
| 프로필 | 이름, 직무, 소개, 사진, 링크, 이메일, GitHub 계정 |
| About me | 소개 콘텐츠 |
| Education | 항목 추가·수정·삭제·순서 변경 |
| Stack | 기술 및 그룹 추가·수정·삭제·순서 변경 |
| Experience | 항목 추가·수정·삭제·순서 변경 |
| Projects | 작성·미리보기·게시·수정·비공개·휴지통·복원 |
| Blog | 작성·미리보기·게시·수정·비공개·휴지통·복원 |
| 카테고리·태그 | 생성·이름 변경·중복 병합·삭제 |
| 미디어 | 이미지·이력서 업로드, 정보 수정, 사용처 확인, 삭제 |
| 홈 설정 | 대표 프로젝트 선택·순서, 프로젝트·블로그 노출 개수 |
| 내보내기 | 콘텐츠와 파일의 수동 내보내기 |

관리자 목록에는 상태·유형별 조회와 내부 검색 등 기본 관리 기능을 제공한다.

**8. 홈 정보의 편집과 게시**

- 프로필, About me, Education, Stack, Experience와 홈 노출 설정은 하나의 홈 초안으로 편집한다.
- 저장과 공개 반영을 분리한다.
- 자동저장한 내용은 공개 홈에 바로 반영하지 않는다.
- 실제 공개 화면과 같은 미리보기를 제공한다.
- ‘홈 변경사항 게시’ 시 홈의 공개 데이터를 한 번에 교체한다.
- 초안에서 항목이나 이미지를 제거해도 현재 공개본에서 사용하는 데이터와 파일을 즉시 영구 삭제하지 않는다.
- 게시되지 않은 초안의 이름·사진·링크·이력서가 공개 조회에 섞이지 않게 한다.

**9. 블로그와 프로젝트 데이터**

공통 항목은 다음과 같다.

- 고유 ID.
- 제목.
- 고유 주소인 slug.
- 짧은 요약.
- Markdown 본문.
- 대표 이미지와 대체 텍스트.
- 대표 이미지의 자르기 위치.
- 카테고리 1개.
- 태그 여러 개.
- 작성일.
- 최초 게시일.
- 마지막 공개 수정일.
- 공개 상태.
- 현재 공개본과 수정 초안의 버전 정보.

블로그 추가 항목 및 동작:

- 읽는 시간을 자동 계산하여 표시한다.
- 관련 글을 제공한다.
- 시리즈 기능은 초기 버전에서 제외한다.

프로젝트 추가 항목:

- 진행 시작일과 종료일.
- 진행 중·완료·보관 상태.
- 개인·팀 프로젝트 구분.
- 담당 역할.
- 팀 규모.
- 사용 기술.
- GitHub·서비스·데모 링크.
- 홈 대표 프로젝트 여부.
- 홈 대표 프로젝트 노출 순서.

프로젝트의 진행 상태와 게시물 공개 상태는 별개로 관리한다. 예를 들어 ‘보관’ 상태의 프로젝트도 공개할 수 있다.

프로젝트 진행 기간과 포스트 최초 게시일도 별개로 관리한다.

프로젝트 작성 시 문제, 담당 역할, 구현 내용, 어려웠던 점, 결과를 작성할 수 있는 기본 템플릿을 제공한다. 본문은 자유롭게 수정할 수 있어야 한다.

**10. 공개본·초안·게시·삭제 흐름**

게시물 공개 상태는 초안, 게시, 비공개, 휴지통으로 구분한다. 게시된 글에는 별도의 수정 초안이 존재할 수 있다.

- 새 글은 초안으로 시작한다.
- 자동저장은 초안만 변경한다.
- 게시 전 미리보기는 관리자만 접근할 수 있다.
- 게시된 글을 수정할 때 기존 공개본은 유지한다.
- ‘수정사항 게시’를 눌러야 변경 내용이 공개된다.
- 수정 초안에는 본문뿐 아니라 제목, 요약, 이미지, 분류 연결, 프로젝트 추가 정보도 포함한다.
- 공개본 교체는 일부 필드만 먼저 반영되지 않도록 일관되게 처리한다.
- 수정사항 폐기 시 기존 공개본은 유지한다.
- 비공개 전환과 휴지통 이동 시 공개 목록·상세·관련 글·홈·사이트맵에서 제외한다.
- 삭제는 우선 휴지통으로 이동한다.
- 휴지통은 자동으로 영구 삭제하지 않는다.
- 복원은 초안 또는 비공개 상태로 처리하여 자동 재공개를 방지한다.
- 영구 삭제는 명시적인 별도 작업으로 제공한다.
- 다른 콘텐츠나 공개본에서 사용 중인 파일은 함께 삭제하지 않는다.

게시 성공 안내는 공개 데이터 교체와 관련 캐시 갱신 처리를 마친 뒤 제공한다. 이미 열려 있는 방문자 화면의 실시간 갱신은 초기 범위에 포함하지 않는다.

초안은 HTML, 데이터 응답, 페이지에 전달되는 데이터, 미리보기, 공유 이미지 등을 통해 비관리자에게 노출되지 않아야 한다.

**11. 날짜와 주소**

- 블로그와 프로젝트 전체 목록은 최초 게시일을 기준으로 정렬한다.
- 기본 정렬은 최신순이다.
- 오래된순으로 변경할 수 있다.
- 같은 게시일의 항목도 고유 ID 등을 보조 기준으로 사용하여 순서를 고정한다.
- 자동저장으로 최초 게시일이나 공개 수정일을 변경하지 않는다.
- 공개 수정일은 수정사항을 게시한 시점으로 갱신한다.
- 비공개 전환·복원·재게시로 최초 게시일을 변경하지 않는다.
- 사용자에게 표시하는 날짜와 시간은 한국 시간 기준이다.
- slug는 영문·숫자·하이픈을 사용하며 동일 유형 안에서 중복되지 않아야 한다.
- 게시 후 제목을 변경해도 slug는 자동으로 변경하지 않는다.
- slug를 직접 변경하면 이전 주소에서 새 주소로 연결한다.
- 삭제·비공개된 글의 이전 주소에서도 접근 권한을 준수한다.

**12. Markdown 편집과 상세 콘텐츠**

다음 문법을 지원한다.

- 제목.
- 일반 문단.
- 굵게, 기울임, 취소선.
- 순서 있는 목록과 순서 없는 목록.
- 체크리스트.
- 인용.
- 구분선.
- 링크.
- 이미지.
- 표.
- 인라인 코드와 코드블록.

편집기 동작:

- PC에서는 입력·미리보기 좌우 분할을 기본으로 한다.
- 모바일에서는 입력·미리보기 전환을 제공한다.
- 이미지 업로드 후 Markdown을 본문에 삽입한다.
- 코드블록에는 언어별 색상과 복사 버튼을 제공한다.
- 본문 제목을 기준으로 목차를 자동 생성한다.
- 편집 미리보기와 공개 화면은 같은 변환 규칙과 본문 스타일을 사용한다.
- 한국어 입력 중 자동저장이나 미리보기 때문에 입력 흐름이 깨지지 않아야 한다.
- 입력 후 잠시 멈추면 자동저장하고, 수동 저장도 제공한다.
- 저장 중·저장 완료·저장 실패와 마지막 저장 시간을 표시한다.
- 저장하지 못한 변경사항이 있는 상태에서 이탈하면 안내한다.
- 여러 탭에서 같은 콘텐츠를 편집할 경우 오래된 버전이 최신 내용을 조용히 덮어쓰지 않도록 충돌을 안내한다.

초기 버전에서는 원시 HTML, 실행 가능한 컴포넌트, MDX 실행 기능, 수식, 다이어그램, 영상 임베드를 제공하지 않는다.

링크는 허용된 주소 형식으로 처리하고, 외부 링크를 새 창으로 여는 경우 필요한 보안 속성을 적용한다.

**13. 작성 중 복구**

- 서버 자동저장과 별도로 기기 내 임시복구 기능을 제공한다.
- 네트워크 오류나 비정상 종료 후 복구 가능한 내용을 안내한다.
- 임시복구 데이터는 관리자 계정과 콘텐츠 단위로 구분한다.
- 오래된 임시복구 내용이 최신 서버 초안을 자동으로 덮어쓰지 않도록 한다.
- 명시적으로 로그아웃하면 기기 내 임시복구 데이터를 정리한다.
- 세션 만료는 명시적 로그아웃과 구분하여 편집 내용을 보존한다.
- 기기 내 임시복구는 정기 백업 기능과 별개다.

**14. 이미지와 미디어**

| 항목 | 요구사항 |
|---|---|
| 등록 | 직접 업로드 기본, 외부 이미지 URL 입력 허용 |
| 업로드 형식 | JPEG·PNG·WebP |
| 이미지 크기 | 파일당 최대 4.5MB |
| 대표 이미지 | 16:9 |
| 자르기 | 중앙 기본, 위치 조절 가능 |
| 대표 이미지 없음 | 제목 중심 카드 |
| 대체 텍스트 | 입력·수정 가능 |
| 본문 이미지 | 클릭 확대, 닫기 버튼과 키보드 조작 제공 |

- 파일 확장자뿐 아니라 실제 파일 유형과 크기를 검증한다.
- 5MB 파일을 지원할 수 있도록 인증된 직접 업로드 등 배포 환경에 맞는 방식을 사용한다.
- 업로드 권한은 관리자에게만 발급한다.
- 업로드 실패와 재시도를 안내한다.
- 외부 이미지 URL은 내 저장소로 가져오는 것을 기본으로 한다.
- 가져오기 실패 시 직접 업로드로 대체할 수 있게 한다.
- 외부 이미지 가져오기에는 크기·형식·주소 검증과 내부 네트워크 접근 차단을 적용한다.

비공개 규칙:

- 게시된 적 없는 초안 이미지는 비공개 저장소에 보관하고 관리자만 조회할 수 있게 한다.
- 수정 초안에 새로 추가한 이미지도 수정사항 게시 전까지 비공개로 유지한다.
- 원본, 축소 이미지, 최적화 결과, 미리보기, 공유 이미지에 같은 원칙을 적용한다.
- 게시된 콘텐츠에서 사용하는 이미지와 아직 게시하지 않은 이미지를 구분한다.
- 이미 공개된 이미지를 초안에서 재사용한다고 비공개 이미지로 취급하지 않는다.
- 외부 원본 서버에 공개된 이미지의 비공개 여부는 이 사이트가 보장하는 범위에 포함하지 않는다.
- 비공개 전환 시 사이트에서 제공하는 이미지 접근과 캐시를 공개 상태에 맞게 처리한다.
- 파일 삭제 전 현재 공개본·초안·다른 콘텐츠의 사용 여부를 확인한다.

**15. 카테고리·태그·기술 목록**

- 블로그와 프로젝트의 카테고리·태그는 독립적으로 관리한다.
- 게시물당 카테고리 1개, 태그 여러 개를 지원한다.
- 글 작성 중 새 분류를 생성할 수 있다.
- 대소문자와 앞뒤 공백 등의 차이로 중복 분류가 생기지 않도록 한다.
- 태그를 클릭하면 같은 콘텐츠 유형의 해당 태그 목록으로 이동한다.
- 여러 태그 선택은 모두 포함하는 조건으로 처리한다.
- 카테고리와 태그를 함께 선택하면 두 조건을 모두 만족하는 항목을 표시한다.
- 사용 중인 카테고리 삭제 시 다른 카테고리로 재배정한다.
- 사용 중인 태그 삭제 시 영향받는 글 수를 안내하고 연결을 해제한다.
- 분류 이름 변경·병합·삭제는 글 자동저장과 구분되는 명시적 관리 작업으로 처리한다.
- 초안에서만 사용 중인 분류가 공개 목록의 필터나 글 수를 통해 노출되지 않도록 한다.
- 프로젝트 사용 기술은 일반 태그와 분리한다.
- 프로젝트에서 Stack 기술 목록을 재사용할 수 있게 한다.
- Stack 기술과 블로그 태그는 자동으로 연결하지 않는다.

**16. 프로젝트·블로그 전체 목록**

두 목록에 다음 동작을 제공한다.

- 기본 최신순, 오래된순 선택.
- 카테고리 필터.
- 여러 태그의 AND 필터.
- 전체 콘텐츠 개수 또는 현재 조건에 맞는 결과 수.
- 최초 12개 표시.
- 이후 12개씩 추가 조회하는 무한스크롤.
- 추가 로딩 표시와 중복 요청 방지.
- 로딩 실패 시 기존 목록 유지와 다시 시도.
- 끝에 도달하면 ‘모든 글을 확인했습니다’ 표시.
- 자동 로딩과 함께 키보드로 사용할 수 있는 ‘더 보기’ 버튼.
- 결과 없음 안내와 필터 초기화.
- 상단으로 바로 가기 버튼.

정렬·필터를 바꾸면 기존 목록과 추가 조회 기준을 초기화한다.

정렬·필터 상태는 URL에 반영하고 새로고침과 공유 후에도 유지한다.

상세 글에서 목록으로 돌아오면 이전 정렬·필터·불러온 목록·스크롤 위치를 복원한다. 그사이 비공개 또는 삭제된 항목은 계속 노출하지 않는다.

상단 이동 버튼을 눌러도 불러온 목록은 유지한다. 버튼은 일정 거리를 스크롤한 뒤 표시하고 모바일의 다른 조작 요소와 겹치지 않게 한다.

전체 프로젝트 목록에서는 홈 대표 프로젝트 순서가 날짜 정렬을 무시하지 않도록 한다.

추가 조회는 전체 데이터를 브라우저로 받은 뒤 나누어 보여주는 방식 대신 서버에서 필요한 묶음을 조회하도록 구현한다.

**17. 상세 페이지**

블로그와 프로젝트에 다음 요소를 제공한다.

- 제목과 요약.
- 대표 이미지가 있는 경우 대표 이미지.
- 카테고리·태그.
- 최초 게시일과 마지막 공개 수정일.
- 자동 목차.
- Markdown 본문.
- 공유 링크 복사.
- 관련 글.
- 이전·다음 글.
- 목록으로 돌아가기.
- 상단 이동 버튼.

블로그는 읽는 시간을 추가로 표시한다. 프로젝트는 기간·진행 상태·역할·팀 규모·사용 기술·외부 링크를 표시한다.

- 이전·다음 글은 같은 콘텐츠 유형의 최초 게시일 순서로 계산한다.
- 관련 글은 같은 유형에서 카테고리·태그가 겹치는 공개 콘텐츠 최대 3개를 표시한다.
- 관련 글이 없으면 해당 영역을 숨긴다.
- 비공개·초안·휴지통 콘텐츠는 연결 대상으로 사용하지 않는다.
- 목록을 거치지 않고 직접 방문한 경우에도 기본 전체 목록으로 돌아갈 수 있어야 한다.

**18. GitHub 활동**

- 프로필 영역에 최근 1년의 공개 GitHub 기여 활동을 표시한다.
- GitHub 프로필로 이동하는 링크를 제공한다.
- 관리자 로그인 상태와 무관하게 방문자가 볼 수 있어야 한다.
- 필요한 토큰은 서버에서 관리한다.
- 주기적으로 갱신하고 캐시하여 방문할 때마다 API를 호출하지 않게 한다.
- API 장애나 제한이 발생해도 포트폴리오 전체가 실패하지 않게 한다.
- 마지막으로 정상 조회한 데이터가 있으면 활용하고, 데이터가 없으면 간단한 안내와 GitHub 링크를 제공한다.
- 초기 버전에서 비공개 저장소 활동 내역이나 비공개 기여 수까지 표시하지 않는다.

**19. 이력서와 연락**

- 공개용 PDF 이력서를 관리자에서 업로드·교체할 수 있게 한다.
- 방문자는 로그인 없이 미리보기와 다운로드를 사용할 수 있어야 한다.
- 파일을 교체할 때도 방문자가 사용하는 이력서 링크를 일관되게 유지한다.
- 새 이력서 업로드만으로 기존 공개 파일이 즉시 교체되지 않도록 홈 게시 흐름에 포함한다.
- 파일 형식과 크기를 검증하고 업로드 제한값은 설정으로 관리한다.
- 등록된 이력서가 없으면 동작하지 않는 다운로드 버튼을 표시하지 않는다.
- 이메일은 프로필의 연락 링크로 제공한다.
- 별도 문의 폼과 메시지 저장 기능은 초기 버전에서 제외한다.

**20. 반응형·접근성·아이콘**

- 모바일, 태블릿, 데스크톱에 대응한다.
- 작은 모바일 화면에서도 페이지 전체 가로 스크롤이 생기지 않도록 한다.
- 긴 코드와 표는 해당 영역 안에서 가로 스크롤한다.
- 헤더·상단 이동 버튼·편집기 버튼이 겹치지 않도록 한다.
- 메뉴·테마·정렬·필터·편집기·이미지 확대를 키보드로 사용할 수 있게 한다.
- 아이콘만 있는 버튼에는 기능을 설명하는 접근성 이름을 제공한다.
- 포커스 위치를 명확히 표시한다.
- 대화상자와 이미지 확대 화면은 열기·닫기 및 포커스 복귀를 처리한다.
- 라이트·다크 모두 본문과 보조 텍스트의 대비를 확보한다.
- 움직임 줄이기 설정을 존중한다.
- 핵심 정보가 마우스 올리기에만 의존하지 않게 한다.

아이콘은 패키지에서 가져와 사용한다.

- 기본 UI 아이콘: `lucide-react`.
- 기술·브랜드 로고: 필요할 때 `react-icons` 등 보충.
- `tabler-icons-react` 등 다른 라이브러리는 실제 필요할 때만 추가.
- 아이콘 크기와 시각적 스타일을 일관되게 유지.

**21. 검색엔진·공유·오류 화면**

- 공개 페이지별 제목과 설명을 제공한다.
- 게시된 콘텐츠만 사이트맵과 검색 노출 대상에 포함한다.
- 게시물별 공유 제목·요약·이미지를 제공한다.
- 공유 이미지 우선순위는 별도 지정 이미지 → 대표 이미지 → 제목 기반 자동 생성 이미지다.
- 제목 기반 공유 이미지는 공개본 데이터로 생성한다.
- 초안과 관리자 페이지는 검색에서 제외하고 실제 접근 권한도 제한한다.
- 무한스크롤과 별개로 검색엔진이 후속 콘텐츠를 발견할 수 있는 주소와 링크 구조를 마련한다.
- 정렬·필터 조합으로 중복 검색 페이지가 과도하게 생기지 않도록 검색 노출 규칙을 정한다.
- 게시·수정·비공개·삭제 시 홈·목록·상세·관련 글·사이트맵·공유 정보의 캐시를 일관되게 갱신한다.
- 없는 주소에는 안내 화면과 홈·목록 이동 링크를 제공한다.
- 로딩·빈 상태·오류 상태를 공개 페이지와 관리자에 각각 구현한다.
- 일반 방문자에게 관리자 초안이나 내부 오류 상세를 노출하지 않는다.

**22. 배포·비용·내보내기**

- 배포는 Vercel을 사용한다.
- 데이터베이스와 비공개 파일 저장소는 Vercel에서 연결·관리하는 구성을 기준으로 선정한다.
- 서비스 선택 시 GitHub 로그인, 비공개 이미지, 직접 업로드, 영속 저장 요구사항을 충족해야 한다.
- 비용 관리는 Vercel 중심으로 한다.
- 구체적인 월 지출 한도와 유료 플랜은 아직 지정되지 않았다.
- 전체 구성이 무료라고 가정하지 말고 필요한 서비스와 비용 발생 항목을 운영 문서에 명시한다.
- 도메인은 구매되어 있으나 Vercel에 연결되지 않은 상태다.
- 환경 변수, GitHub 인증 설정, 도메인 연결 절차를 문서화한다.
- 개발·미리보기 환경에서 운영 콘텐츠를 실수로 변경하지 않도록 환경을 구분한다.

초기 버전에서 정기 백업 자동화와 자동 보관 정책은 제외한다.

관리자 전용 수동 내보내기는 제공한다.

- Markdown 원문.
- 제목·요약·날짜·slug 등 메타데이터.
- 카테고리·태그와 연결 정보.
- 프로젝트 추가 정보.
- 홈 콘텐츠와 설정.
- 직접 저장한 이미지·이력서 및 파일 연결 정보.
- 공개본과 초안을 구분할 수 있는 정보.

초안과 비공개 파일이 포함된 내보내기 결과를 공개 주소에 남기지 않도록 한다.

**23. 초기 버전에서 제외할 기능**

- 방문자 회원가입과 일반 회원.
- 공개 사이트의 키워드 검색.
- 댓글·좋아요·조회수.
- 구독·뉴스레터.
- 문의 폼.
- 다국어.
- 블로그 시리즈.
- 예약 발행.
- 상세 변경 이력 UI.
- 원시 HTML과 실행 가능한 MDX.
- 수식·다이어그램·영상 임베드.
- 드래그 기반 페이지 빌더.
- 정기 백업 자동화.

현재 공개본과 수정 초안을 분리하고 덮어쓰기 충돌을 방지하는 기능은 변경 이력 UI와 별개로 반드시 구현한다.

**24. 구현과 산출물**

기존 프로젝트가 있으면 먼저 구조와 설정을 확인하고 활용한다. 구체적인 데이터베이스, 인증 도구, 편집기, 저장소 라이브러리는 요구사항과 배포 환경에 맞게 선정하고 이유를 기록한다.

완료 시 다음을 제공한다.

- 실행 가능한 소스.
- 데이터베이스 구조와 초기 설정·변경 적용 방법.
- 비밀값 없는 환경 변수 예시.
- 개발 실행과 배포 방법.
- GitHub 관리자 계정 설정 방법.
- 이미지·이력서 저장소 설정 방법.
- 도메인 연결 방법.
- 콘텐츠 작성·게시·수정·복원·내보내기 운영 안내.
- 주요 검증 결과.
- 실제 개인 자료나 외부 계정 설정이 없어 완료하지 못한 항목의 명확한 목록.

실제 데이터 저장이 연결되지 않은 임시 화면이나, 인증이 없는 관리자 화면을 완성본으로 처리하지 않는다.

**25. 완료 검증 기준**

다음 시나리오를 확인한다.

1. 홈 섹션이 지정된 순서로 표시되고 빈 섹션과 메뉴가 함께 숨겨진다.
2. 홈 대표 프로젝트 수·순서와 블로그 노출 수를 관리할 수 있다.
3. 모바일 메뉴와 고정 헤더가 정상 동작하고 이동한 제목이 가려지지 않는다.
4. 테마 선택이 유지되고 첫 화면 깜빡임이 없다.
5. 허용된 GitHub 계정만 관리자 세션을 얻는다.
6. 비로그인·미허용 계정의 직접 조회·변경 요청을 서버에서 차단한다.
7. 공개 글 수정 중 자동저장해도 기존 공개본은 유지된다.
8. 수정사항 게시 시 본문과 메타데이터가 함께 반영된다.
9. 초안 데이터와 미게시 이미지가 공개 조회·공유·이미지 경로로 노출되지 않는다.
10. 새로 추가한 수정 이미지가 게시 전까지 비공개로 유지된다.
11. Markdown 미리보기와 공개 본문이 같은 규칙으로 표시된다.
12. 자동저장 실패·세션 만료·비정상 종료 후 편집 내용을 복구할 수 있다.
13. 여러 탭의 오래된 내용이 최신 초안을 조용히 덮어쓰지 않는다.
14. 두 목록의 날짜 정렬, 태그 AND 필터, 무한스크롤에 중복·누락 문제가 없다.
15. 상세에서 돌아오면 목록 조건과 위치가 복원된다.
16. 비공개·휴지통 콘텐츠가 홈·목록·상세·관련 글에서 제외된다.
17. 4.5MB 이미지 업로드, 제한 초과 거절, 파일 형식 검증이 정상 동작한다.
18. 파일 삭제 시 다른 공개본·초안에서 사용하는 파일을 보호한다.
19. 이력서 미리보기·다운로드·교체가 정상 동작한다.
20. GitHub API 실패가 포트폴리오 전체 오류로 이어지지 않는다.
21. 모바일·데스크톱과 두 테마에서 레이아웃과 접근성을 확인한다.
22. 데이터와 파일이 새로고침·재배포 후에도 유지된다.
23. 내보내기 결과에 콘텐츠와 파일 연결 정보가 포함된다.
24. 실행·배포·관리에 필요한 문서가 제공된다.

실행하지 못한 검증은 통과로 표시하지 않고 필요한 설정과 함께 명시한다.
