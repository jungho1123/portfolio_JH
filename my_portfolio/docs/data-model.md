# 데이터 구조와 변경 적용

`prisma/schema.prisma`와 체크인된 SQL 마이그레이션이 기준입니다. Prisma 7은 `prisma.config.ts`에서 Next.js 환경 파일을 로드하고 직접 연결 URL을 우선 사용합니다.

| 모델                                    | 역할                                                                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| User / Account / Session / Verification | Better Auth 영속 인증. 역할 필드는 기존 DB 호환용이며 GitHub 계정 고유 ID를 추가 검증합니다.                          |
| Content                                 | HOME/BLOG/PROJECT 구분, 공개 상태, 낙관적 잠금 번호, 최초·최근 게시일, 현재 초안/공개본 포인터. 홈 ID는 `home`입니다. |
| Revision                                | Markdown·메타데이터·홈 구조를 담는 JSONB와 파일·분류 연결. 현재 초안과 공개본만 유지합니다.                           |
| Slug                                    | 콘텐츠 유형별 고유 주소 예약과 실제 게시된 과거 주소. 미게시 예약은 공개 주소로 해석하지 않습니다.                    |
| Taxon / RevisionTaxon                   | 유형별 카테고리·태그와 버전별 연결. 정규화 이름에 유일성 제약이 있습니다.                                             |
| Media / MediaUse                        | 비공개 Blob 경로·검증 상태·메타데이터와 버전별 참조. FK로 사용 중인 파일을 보호합니다.                                |
| GithubCache                             | 공개 GitHub 활동의 마지막 정상 결과와 최근 갱신 시도 시각.                                                            |
| CacheJob                                | DB 게시 작업 후 처리해야 할 캐시 무효화 작업. 성공한 작업만 제거합니다.                                               |

초안 저장과 게시·상태 변경은 Serializable 트랜잭션과 예상 revision 번호를 사용합니다. 공개본은 게시 시 새 Revision으로 생성합니다. 자동저장이 공개본을 변경하지 않습니다. 게시물 분류 관리 작업은 명시적 전역 변경이므로 관련 공개본·초안의 참조를 함께 변경하고 편집 잠금 번호도 올립니다.

프로젝트 기술 ID는 홈 Stack의 게시된 기술 목록에서 선택합니다. 프로젝트 게시 시 기술 표시 정보를 복사하므로 미게시 홈 Stack 변경이 공개 프로젝트에 섞이지 않습니다. 홈의 대표 프로젝트 선택·순서는 홈 초안에 저장되며 홈 게시 시 반영됩니다.

`Content`의 `(kind, state, firstPublishedAt, id)` 인덱스와 날짜+ID 커서로 12개씩 조회합니다. 파일의 공개 접근은 단일 public 플래그가 아니라 `MediaUse → Revision → 현재 공개 Content` 존재 여부로 판단합니다. 다른 공개 콘텐츠에서 같은 파일을 사용하면 그 파일은 계속 공개됩니다.

새 마이그레이션은 `pnpm exec prisma migrate dev --name <이름>`으로 개발 DB에서 만들고 운영에는 `pnpm db:deploy`로 적용합니다. 운영 데이터의 초기화나 기존 마이그레이션 편집은 하지 않습니다. JSONB 내용도 `lib/schemas.ts`의 Zod 스키마로 검증하며, 구조를 변경할 때는 기존 JSONB 문서의 변환을 포함해야 합니다.
